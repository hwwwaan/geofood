# 그날, 어디에서는

생년월일을 넣으면 그 무렵 전국 어딘가에서 나던 먹거리 하나를 배정하고,
**지리적 표시로 등록된 134가지를 전부 펼쳐** "아는 이름은 그중 몇 개뿐"임을 보여주는 정적 웹사이트.

- 배포본: **https://hwwwaan.github.io/geofood/**
- 발표: 2026년 8월 24일

> 영광 한 곳에서 시작해 2026-08-18에 전국으로 넓혔습니다.
> 저장소 이름도 `yeonggwang-food` 에서 `geofood` 로 바꿨고 QR을 다시 뽑았습니다.
> 옛 주소는 깃허브가 새 주소로 넘겨주지만, 배포할 QR은 새 것을 쓰세요.

## 로컬에서 보기

**`index.html` 을 더블클릭하면 열립니다.** 데이터가 파일 안에 들어 있어 서버가 필요 없습니다.

## 파일

| 파일 | 무엇 |
|---|---|
| `index.html` | **생성물입니다. 직접 고치지 마세요.** 61KB, 이 한 장이 전부입니다 |
| `10-work/전국판/_template.html` | 화면을 고칠 때 여기를 고칩니다 |
| `10-work/전국판/build-data.py` | 등록현황 → `items-national.json` |
| `10-work/전국판/build.py` | 위 둘을 합쳐 `index.html` 을 다시 씁니다 |
| `yeonggwang/` | **영광판.** 지우지 않고 남겨뒀습니다 |
| `00-brief/` `10-work/` `20-assets/` `30-out/` `40-ref/` | 과제·작업·재료·제출본·참고 |

```bash
python3 10-work/전국판/build.py     # 데이터·화면을 고친 뒤 다시 만들기
node yeonggwang/sim.js              # 영광판 배정 로직 검증
```

## 화면

| 주소 | 화면 |
|---|---|
| `#/` | 생년월일 입력. 그게 전부입니다 |
| `#/result?d=1997-06-12` | 배정 결과. **이 주소를 공유하면 같은 결과가 나옵니다** |
| `#/map` | 134가지 전체. 같은 이름끼리 / 지역순 / 달력순 |
| `#/impact` | 노출 분산도. 10,000건을 브라우저에서 그 자리에서 계산 |

**결과 화면에서 할 수 있는 것**

- **결과 카드 이미지로 저장** — 캔버스로 1080px 정사각 PNG를 그 자리에서 만듭니다.
  모바일에서는 공유 시트가 뜨고, 데스크톱에서는 파일로 내려받습니다. 외부 라이브러리를 쓰지 않습니다
- **주소 복사해서 보내기** — 날짜 문장과 주소를 같이 복사합니다. 받은 사람이 열면 같은 결과가 나옵니다

## 지켜야 할 것

- **생년월일은 예측이 아니라 배정 장치입니다.** 취향을 묻기 시작하면 인기 품목에 노출이 더 몰립니다
- **인지도를 추정하지 않습니다.** 134개를 눈대중으로 매기면 그 순간 근거가 사라집니다.
  대신 「같은 품목이 몇 곳에 등록됐나」를 데이터에서 셉니다
- **빈 곳을 지어내지 않습니다.** 없으면 없다고 화면에 적습니다
- 사주·운세 어투를 쓰지 않습니다. 근거는 사주가 아니라 수확기입니다

## 아직 못 채운 것

- **수확기가 작물 일반 기준입니다.** 등록 지역의 실제 수확기를 확인한 값이 아닙니다
- **임산물 지리적표시(산림청 소관)가 빠져 있습니다.** 수산물도 현재 유효 등록이 24건이라
  제1~17호 중 일부는 말소됐을 수 있습니다
- **연중 품목 27가지가 열두 달 내내 후보로 들어가** 한 달만 제철인 품목보다 열두 배 유리합니다.
  고칠 수는 있지만 그러면 지표가 아무것도 재지 않게 됩니다. 아직 안 정했습니다
- **현실의 노출 편중 기준선이 없습니다.** 이게 없으면 "우리가 개선했다"를 말할 수 없습니다
