# 영광 먹거리 배정 서비스 — 프로젝트 명세

> 이 문서를 Claude Code 작업 디렉터리에 두고 그대로 참조시키면 됩니다.
> `items.json`과 `core.js`가 같은 폴더에 있어야 합니다.

---

## 0. 한 줄

생년월일을 입력하면, 그 시기 영광에서 나는 먹거리 하나를 **배정**해 보여주고, 마지막에 영광의 먹거리 전체를 펼쳐 "굴비는 그중 하나"임을 드러내는 웹 서비스.

---

## 1. 설계 원칙 (이걸 어기면 프로젝트가 무너집니다)

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **생년월일은 예측이 아니라 배정 장치다** | 취향 기반 추천을 만들면 인기 품목(굴비)에 노출이 더 몰린다. 우리가 풀려는 문제를 우리가 강화하게 된다 |
| 2 | **결과는 결정론적이다** | 같은 생년월일은 언제나 같은 결과. 랜덤이면 "내 것"이라는 느낌도 공유 동기도 사라진다 |
| 3 | **근거는 사주가 아니라 제철이다** | "당신이 태어난 날 영광에서는 이것을 거두고 있었습니다" — 절기·수확기가 근거 |
| 4 | **MBTI는 품목을 고르지 않는다** | 품목은 생년월일이 정한다. MBTI는 같은 품목을 어떻게 보여줄지(편집 방향)만 정한다 |
| 5 | **앵커(굴비)는 배정에서 제외한다** | 단 전체 지도에는 반드시 넣는다. 빼면 "굴비를 부정한다"가 되고, 넣어야 "굴비 뒤에 21개가 더 있다"가 된다 |
| 6 | **노출 분산도를 측정한다** | 참여자 수·조회수는 산출. 성과는 품목별 노출이 얼마나 고르게 퍼졌는가 |

## 2. 화면 3단

### [1] 입력
- 생년월일 (필수) — 연/월/일 셀렉트 또는 date input
- MBTI (선택) — 4축 토글 또는 16개 선택. **건너뛰기 가능해야 함**
- 카피 예시: "당신이 태어난 날, 영광에서는 무엇을 거두고 있었을까요"

### [2] 결과 — 배정된 품목 1개
표시 순서:
1. **날짜 문장** — "1997년 6월 12일. 그 무렵 영광에서는 찰보리를 거두고 있었습니다."
2. **품목 카드** — 이름 / 한 줄 소개 / 제철 표시
3. **본문** — MBTI에 따라 편집 방향 분기 (없으면 기본형)
4. **왜 몰랐을까 한 줄** — 앵커 그림자를 자연스럽게 심는 문장
5. **어디서 사나** — 판매처 링크
6. CTA: "영광에는 이런 게 몇 개나 더 있을까요" → [3]으로

### [3] 전체 지도 — 이 화면이 핵심
- 영광 먹거리 22종을 **인지도 낮은 순**으로 전부 나열
- 굴비는 목록 **맨 아래** 한 칸에만 등장. 캡션: "그리고 굴비. 우리가 아는 하나."
- 월별 타임라인 뷰 토글 (1~12월에 무엇이 나는지)
- 하단에 문제 제기 한 문단 — 지리적 표시 6종 vs 미등록 굴비의 대비

> **[3]이 없으면 이 서비스는 그냥 재미 콘텐츠입니다.** 개인 결과 하나로 끝나면 문제 정의가 전달되지 않습니다.

## 3. 기술 스택

- **정적 사이트.** 백엔드 없음. GitHub Pages 배포 가능해야 함
- HTML + CSS + Vanilla JS (ES modules) 또는 React 단일 페이지
- 외부 의존성 최소화. 빌드 없이 열려도 동작하면 최상
- 모바일 우선 (발표장에서 QR로 접속시킬 것)
- `items.json`을 fetch로 로드. 로컬 확인 시 `python3 -m http.server`

## 4. 디자인 토큰

팀 발표 덱과 같은 세이지-그레이 계열로 맞춥니다.

```css
--ink:        #383838;  /* 본문·제목 */
--sage:       #7E8C8A;  /* 액센트·헤더 */
--sage-2:     #9CACA9;
--sage-3:     #ABBDBA;
--line:       #CED5D2;
--tint:       #F0F3F2;  /* 카드 배경 */
--bg:         #FFFFFF;
--emphasis:   #000000;
```

- 폰트: Pretendard (한글), 숫자는 Arial
- 모서리 반경 8~12px, 여백 넉넉하게
- **애니메이션은 결과 등장에만.** 사주 사이트처럼 과하게 굴리지 말 것
- 톤: 점술이 아니라 기록. "운명"이 아니라 "그날 그곳"

## 5. 배정 로직 (core.js 참조)

```
입력: birthdate (YYYY-MM-DD), mbti (optional)

1. seed = hash(birthdate)                    // 결정론적
2. candidates = items.filter(제철에 birthdate의 월이 포함 && !isAnchor)
3. candidates 비면 → 연중 품목(alwaysAvailable)으로 폴백
4. weight = mode === 'uniform' ? 1 : (6 - awareness)
5. pick = weightedPick(candidates, weight, seed)
6. copy = buildCopy(pick, mbti)
```

**mode 파라미터를 반드시 남겨두세요.**
- `uniform` — 균등 배분 (기본값)
- `inverse` — 인지도 역가중 (덜 알려진 품목이 더 자주 뽑힘)

두 모드의 분산도를 비교하는 것 자체가 발표 재료가 됩니다.

## 6. 임팩트 측정 — 코드에 넣을 것

`core.js`의 `metrics` 객체를 사용합니다.

| 지표 | 함수 | 의미 |
|---|---|---|
| 지니계수 | `gini(counts)` | 0에 가까울수록 고르게 분배. **핵심 지표** |
| HHI | `hhi(counts)` | 집중도. 낮을수록 좋음 |
| 비앵커 비중 | `nonAnchorShare(...)` | 굴비 외 품목 노출 비율 |

**시뮬레이션 스크립트를 하나 만들어 두세요.** 생년월일 10,000건을 무작위 생성해 돌리고 위 세 지표를 출력합니다. 이게 발표의 임팩트 슬라이드 숫자가 됩니다.

```
현실(추정): 영광 검색·노출의 대부분이 굴비 → 지니계수 높음
우리 서비스: 지니계수 0.0X → "노출을 이만큼 고르게 분배했다"
```

> 현실 기준선은 아직 없습니다. 네이버 데이터랩 검색량으로 만들 수 있는지 확인 필요 — **[확인필요]**

## 7. 데이터 스키마 (items.json)

```jsonc
{
  "id": "chalbori",
  "name": "찰보리쌀",
  "category": "곡물",
  "months": [6],                 // 제철/수확 월 (1-12)
  "alwaysAvailable": false,      // 연중 구매 가능 여부
  "awareness": 2,                // 1(무명) ~ 5(전국구)
  "isAnchor": false,             // 굴비만 true
  "tagline": "국내 유일 보리산업 특구에서 나는 찰보리",
  "why": "...",                  // 왜 안 알려졌나 한 줄
  "note": "...",                 // 본문 재료
  "verified": false,             // 수확기 원자료 확인 여부
  "source": "..."
}
```

**`verified: false`인 항목은 화면에 "확인 중" 배지를 달거나, 발표 전까지 원자료로 채워야 합니다.** 지금 대부분의 `months`는 일반적인 작물 수확기 기준이고 영광군 원자료로 확인하지 않았습니다.

## 8. 만들지 말아야 할 것

- ❌ 사주·운세 해석 문구 ("당신의 기운은…") — 임팩트 논증이 통째로 무너집니다
- ❌ 취향 설문 기반 추천 — 원칙 1 위반
- ❌ 결제·주문 기능 — 3주 안에 안 되고, 판매처 링크로 충분
- ❌ 로그인 — 개인정보 수집 이유가 없습니다
- ❌ localStorage에 생년월일 저장 — 필요 없고 리스크만 생깁니다

## 9. 작업 순서 (권장)

1. `items.json` 스키마 검증 + 로더
2. `core.js` 배정 로직 단위 테스트 (같은 입력 → 같은 출력 확인)
3. 시뮬레이션 스크립트 → 분산도 지표 출력
4. [2] 결과 화면
5. [3] 전체 지도 — **여기에 시간을 가장 많이 쓸 것**
6. [1] 입력 화면
7. 모바일 반응형 + QR 배포
