## 2. 구조 확정 후 — 배정 로직 검증

```
구조 좋습니다. 이 순서로 갑니다.

3. 12개월 각각에 대해 후보 품목이 몇 개인지 표로 출력
   (제철 품목이 0개인 달이 있으면 폴백이 걸리므로 확인 필요)
4. verified:false인 품목이 몇 개인지 카운트

결과를 표로 보여주고, 이상한 게 있으면 짚어주세요. UI는 아직 만들지 마세요.

## 5. 입력 화면 + 연결 (SPEC의 [1])

```
[1] 입력 화면을 만들고 세 화면을 연결해주세요.

- 생년월일: 모바일에서 조작하기 쉬운 방식으로. date input이 iOS/안드로이드에서
  어떻게 보이는지 고려해서 선택하고, 왜 그렇게 했는지 알려주세요.

  16개 그리드보다 4축 토글이 빠를 것 같은데, 판단해서 만들고 이유를 말해주세요.
- 라우팅은 해시 기반으로 (#/result?d=1997-06-12&m=INFP).
  결과 URL을 공유하면 같은 결과가 나와야 합니다.
- localStorage에 생년월일을 저장하지 마세요.

## 6. 카피 다듬기 — 이건 별도로

```
지금 화면에 들어간 모든 문구를 검토해주세요. 코드는 건드리지 말고 문구만입니다.

기준:
- 사주·운세 어투 금지. "당신의 기운", "타고난", "인연" 같은 말이 있으면 전부 교체
- 우리가 쓰는 어투는 점술이 아니라 기록입니다. "그날 그곳에서 무엇이 났는가"
- em dash(—)를 남발하지 마세요. 한 화면에 하나 이상 쓰지 마세요
- 명사구를 길게 이어붙이지 마세요. "지역 먹거리 인지도 개선 서비스" 같은 표현 금지
- 감탄사와 과장 금지. "놀랍게도", "무려", "특별한" 같은 말 빼세요
- 한 문장은 짧게. 두 줄을 넘기면 자르세요

바꾼 문구를 before/after 표로 보여주세요.
```
